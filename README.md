# printer_hub
# Journal Inspector

## Назначение

Данная ветка содержит прототип агента для чтения событий CUPS из systemd-journal с использованием библиотеки `libsystemd`.

Основная цель — проверить возможность получения информации о заданиях печати напрямую из журнала системы без анализа лог-файлов CUPS.

## Реализовано

Приложение:

* подключается к локальному `systemd-journal`;
* переходит к концу журнала при запуске;
* отслеживает появление новых записей в режиме реального времени;
* фильтрует сообщения процесса `cupsd`;
* извлекает основные поля записи:

  * `_HOSTNAME`
  * `_COMM`
  * `SYSLOG_IDENTIFIER`
  * `MESSAGE`
  * время события (`realtimeUsec`);
* выводит полученные данные в консоль.

## Пример вывода

```text
HOST    : server01
COMM    : cupsd
SYSLOG  : cupsd
TIME    : 1780993446803385
MESSAGE : REQUEST localhost - - "POST / HTTP/1.1" 200 182 Renew-Subscription client-error-not-found
```

## Текущий результат

Подтверждено, что через `systemd-journal` доступны внутренние сообщения демона CUPS в режиме реального времени.

Получены события:

* обращения клиентов к CUPS;
* операции IPP;
* диагностические сообщения;
* статистические отчёты CUPS;
* сведения о состоянии сервера печати.

## Ограничения текущей реализации

На данном этапе приложение:

* не сохраняет данные;
* не выполняет парсинг сообщений;
* не выделяет задания печати в отдельные сущности;
* не отправляет информацию на сервер;
* работает только как консольный монитор.

## Следующие шаги

Планируется:

1. Определить сообщения, содержащие информацию о заданиях печати.
2. Извлекать:

   * идентификатор задания;
   * пользователя;
   * принтер;
   * название документа;
   * статус задания.
3. Формировать структурированные объекты событий.
4. Передавать данные в систему учёта печати.
5. Реализовать работу в режиме фонового агента.

## Сборка

```bash
mkdir build
cd build

cmake ..
make
```

## Запуск

```bash
./journal-inspector
```

Для работы требуется установленная библиотека `libsystemd`.
